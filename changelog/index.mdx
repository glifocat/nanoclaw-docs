<Update label="v2026.10.0" description="2026-10-09" tags={["Breaking", "Feature", "Fix", "Skill"]}>
  Released 2026-10-09 as [v2026.10.0](https://github.com/nanocoai/nanoclaw/releases/tag/v2026.10.0) (`7203e00d`), the first release with calendar version numbers (`YYYY.M.PATCH`). Update with `/update-nanoclaw`; read **Before you update** first.

  **Before you update**

  - **Breaking: if you use the OneCLI gateway, move it to exactly 1.42.0 before you rely on the update.** On an older gateway every vault call fails, and setup stops with "OneCLI gateway lacks the /v1 API required by the installed SDK". `/update-nanoclaw` does not upgrade a running gateway for you; follow `docs/onecli-upgrades.md` in your NanoClaw folder, which also says when the step does not apply. Do not go past 1.42.0: 1.43 and later are not supported yet. New installs already get 1.42.0.
  - **`/update-nanoclaw` now installs the newest release, not the tip of `main`.** `NANOCLAW_UPDATE_CHANNEL` in `.env` picks the channel: `stable` (the default) follows releases, `beta` takes release candidates, and `edge` follows `main`. To keep following `main`, run `pnpm exec tsx scripts/update-nanoclaw.ts set-channel --channel edge` in your NanoClaw folder.
  - **Iron Proxy installs: rerun the Iron setup once after updating** so the approval front is rebuilt with this release's checks: `pnpm exec tsx .claude/skills/add-iron-proxy/scripts/setup.ts` from your NanoClaw folder. Add `--with-control` if you use the Iron Control console.

  **New**

  - **Iron Proxy can reach a keyless model on the same machine over plain HTTP**, for example `http://host.docker.internal:<port>/v1`. See [Credential gateways](/operate/gateways).
  - **The service can use an outbound proxy** from `HTTPS_PROXY`, `HTTP_PROXY` or `ALL_PROXY`, and `NO_PROXY`, set in your setup shell or `.env`.
  - **Iron Proxy can skip the approval card for reads that send no credential** when you set `NANOCLAW_GATEWAY_UNCREDENTIALED_READS=true` in `.env`. It is off by default.
  - **A failed Claude run shows Claude's own short reason** in the chat for known failures, such as an invalid API key.

  **Fixes**

  - **`/update-nanoclaw` and rollback are more dependable.** A rollback swaps your `data/` snapshot back in by rename instead of deleting it first.
  - **New Claude groups no longer default to the `Concise` output style.** A group that already has an output style keeps it.
  - **`/add-dial-tool` works again on OneCLI gateway 1.42.0.**
  - **Security:** WhatsApp moves to Baileys 7.0.0-rc14, agents can no longer redirect host file operations outside their own folders, and the other names the Claude SDK accepts for admin commands (such as `/reset` for `/clear`) are now admin-only too. On Linux, if your outbound proxy has a password, rerun `pnpm exec tsx setup/index.ts --step service` to move it out of your service file into a private file. See the [release notes](https://github.com/nanocoai/nanoclaw/releases/tag/v2026.10.0) for the full list.
</Update>

<Update label="v2.4.0" description="2026-09-23" tags={["Breaking", "Feature", "Fix", "Skill"]}>
  Released 2026-09-23 as [v2.4.0](https://github.com/nanocoai/nanoclaw/releases/tag/v2.4.0) (`143db6c9`). Update with `/update-nanoclaw`; read the two breaking items first. Upstream [Updating to NanoClaw 2.4](https://github.com/nanocoai/nanoclaw/blob/main/docs/release-2.4-update.md) has the full procedure.

  **Before you update**

  - **Breaking: credential gateways install through skills, and the host refuses to start without one.** `/add-onecli` supplies OneCLI and `/add-iron-proxy` adds optional Iron Proxy support. OneCLI stays the Standard setup default, the gateway picker appears only in Advanced setup, and upgrades keep the existing selection. Setting `NANOCLAW_GATEWAY_PROVIDER` alone installs nothing. **Migration:** `/update-nanoclaw` installs the selected gateway before cutover; a hand-merged fork must run `/add-onecli` (or its gateway's skill) before restarting. See [Credential gateways](/operate/gateways).
  - **Breaking: custom source that composes agent instructions must move to the new module.** `src/claude-md-compose.ts` is now `src/project-doc-compose.ts` and `composeGroupClaudeMd(group)` became `composeGroupProjectDoc(group, groupDir, spec)`; the `/app/CLAUDE.md` and `.claude-fragments` mounts are gone, and every instruction section now reaches the model. Standard installations need no source edits.
  - **Claude groups with no model set move to Opus 5.5**, which changes cost and usage-limit burn. Set `NANOCLAW_DEFAULT_MODEL` in `.env` or `ncl groups config update --id <group> --model <model>` before updating to keep a model.
  - **Codex groups with no model set start new threads on `gpt-6-astra`** (`/add-codex` pins `@openai/codex` 0.155.1); groups with a model, and existing threads, keep theirs. Pin with `ncl groups config update --id <group-id> --model gpt-5.6-sol`, then `ncl groups restart --id <group-id>`.
  - **Claude agents default to a concise tone** unless the group's Claude settings already set `outputStyle`.
  - **Existing OpenCode installs must re-run `/add-opencode`**, rebuild the agent image, and restart.
  - **Cutover stops this install's agent containers itself.** `/update-nanoclaw` no longer waits on an idle container; an agent mid-turn loses that turn. See [Upgrading](/operate/upgrading).

  **New**

  - **Iron Proxy is an alternative local gateway** with the Iron Control web console; Codex works through it, including WebSocket turns. See [Credential gateways](/operate/gateways).
  - **Echo's hardened image and a managed Slack app are set up through the community portal** with one browser sign-in. See [Echo hardened runtime](/guides/echo-hardened-runtime).
  - **Install-wide model and speed knobs.** `NANOCLAW_DEFAULT_MODEL` fills in a group's missing model and `NANOCLAW_FAST_MODE=1` enables the faster, pricier tier. The host reads both from `.env` at startup, so restart the host after changing them; each group then picks the value up at its next container start. `ncl groups config update --id <group-id> --speed fast` sets the tier per group. See [Configuration](/operate/configuration).
  - **Mattermost is a channel** via `/add-mattermost`. See [Mattermost](/channels/mattermost).
  - **The OpenCode provider is reworked** with host-managed authentication and model selection. See [Agent providers](/extend/providers).
  - **Host restarts keep approvals and delivery state.** Approval cards, retry counts, and session claims live in the central database, and a second host in the same checkout no longer takes over a running host's `ncl` socket.
  - **`ncl status` shows the running host process and its connected channel adapters.** Agents run on Claude Code 2.1.280, and the Slack companion skills ship on `main`.

  **Fixes**

  - Codex turns wait for every MCP server to start instead of completing with nothing sent; replies stay in the thread they answer; busy installs no longer see latency grow with session count.
  - Quoted `.env` values read the same in setup and the host, and `WEBHOOK_PORT` is read from `.env`. See [Environment variables](/reference/environment-variables).
  - `/update-nanoclaw` loads its controller again and is correct on macOS; setup is sturdier on Linux; concurrent SQLite migrations no longer fail setup.
  - `ncl tasks update` rejects an empty `--prompt`; `send_card` link-only actions and `ask_user_question` are described to agents. See [ncl reference](/reference/ncl-cli#tasks).
  - **Security:** setup redacts resolved secrets in skill logs, the agent image is repinned to `hardened-2026-08-24` on Bun 1.4.0, and pnpm's 3-day `minimumReleaseAge` gate is enforced.
</Update>

<Update label="v2.3.0" description="2026-08-24" tags={["Breaking", "Feature", "Fix", "Skill"]}>
  - **Breaking: the container runtime moves behind a session driver seam.** Each session is composed as a validated, admission-checked spec and realized by a selectable driver (`src/drivers/`; Docker ships built-in and stays the default). Three surfaces break. **(1)** Group folder names must now match the runtime label grammar: at most 63 characters of `[A-Za-z0-9_-]`, alphanumeric at both ends. Previously legal 64-character names, trailing `-`/`_`, and unvalidated legacy imports refuse to spawn. **(2)** Container names change from `nanoclaw-v2-<folder>-<timestamp>` to key-derived `ncl-…` names, and invocation changes from `docker run` to `create` + `start --attach`. The old human-readable name survives as the `nanoclaw-container-name` label, so name-based tooling, Docker allowlists, and audit rules should match by label instead (`docker ps --filter label=nanoclaw-session` or `--filter label=nanoclaw-group-folder=<folder>`). **(3)** Internal container helpers (`hostGatewayArgs`, `readonlyMountArgs`, `stopContainer`, `ensureContainerRuntimeRunning`, `cleanupOrphans`, `buildContainerArgs`) moved into the driver module, so customized installs importing them stop compiling. The `/use-native-credential-proxy` skill is retired: the spec's admission rules refuse credential values in container env on every lane. Credentials ride the OneCLI vault, and custom Anthropic endpoints use the `ANTHROPIC_BASE_URL` + placeholder-token pattern from setup. **Migration:** run `bun scripts/detect-driver-migration.ts`. It detects all three surfaces and prints one finding per line with a minimal fix instruction; nothing detected means nothing to do (#3308, #3429, #3442)
  - **Breaking: central database access is asynchronous behind `DbDriver`.** SQLite remains the default and existing `data/v2.db` files are unchanged, but custom source and installed channel or provider extensions must await central reads and writes and adopt the retyped host seams. Composition and migrations are backend-ready: a one-slot driver registry keeps backend selection in `src/db/compose.ts`, and `pnpm run migrate` is the explicit schema-change path. **Migration:** follow upstream `docs/central-db-async-migration.md` to find affected calls, preserve transaction boundaries, verify, or roll back (#3334, #3335)
  - **Breaking: agent mailbox access goes through storage-neutral host and runner registries.** The built-in SQLite implementation preserves existing session data and runtime behavior, but custom source may need to replace raw session-database access, await mailbox writes, and adopt the moved runner state and heartbeat helpers. Scheduled-task lifecycle semantics tightened in the same series: deleting an isolated task cascades its session state. **Migration:** follow upstream `docs/agent-mailbox-seam-migration.md` for the detect grep, old-to-new symbol map, verification, and rollback (#3349)
  - **Breaking: the host runtime requires Node.js 22 or newer.** Node 20 is not supported by the upgraded `better-sqlite3` release used for current Node runtimes (`engines.node` is now `>=22`). **Migration:** run `bash setup/install-node.sh`, verify `node --version` reports v22 or newer, then rerun `/update-nanoclaw` (#3360, #3443)
  - **Breaking (decision gate): a new Slack experience is offered to classic single-bot installs.** It brings per-agent provisioned Slack apps, agent spawning from Slack, and UX improvements. Classic Slack keeps working unchanged; the gate asks for a decision, not a forced migration. **Migration:** run `/migrate-slack-agents`. It detects classic state and either walks the upgrade or records the choice to stay on classic; both outcomes satisfy the update requirement (#3357, #3391, #3404)
  - **Mid-turn streaming is the only content door out of a turn.** For providers that emit mid-turn text, closed `<message to="...">` blocks are delivered as they are emitted, with cross-segment assembly of blocks split across streaming segments. The final result never delivers content: a turn that delivered nothing but whose result still carries content gets a wrap nudge, and the retry streams through the same mid-turn door (#3284)
  - **Host restarts adopt running sessions instead of restarting them.** A service restart no longer kills in-flight agent work; to apply image or runtime changes to a group, restart it deliberately with `ncl groups restart`. Containers spawned before this release cannot be adopted and are removed at first upgraded startup (#3308)
  - **Adapters gain lifecycle hooks and richer declarations.** The additions: membership-change, session-created, post-delivery, and wizard hooks, an extend tool, a per-adapter `sessionMode` declaration, and a `decline_notify` unknown-sender policy that declines while telling the sender it did (#3292, #3293, #3294, #3295, #3296, #3297, #3304, #3361)
  - **Session specs validate runtime isolation tiers.** The driver contract validates `runtimeTier` against its isolation capabilities at spawn. The shipped Docker driver supports `container`; trunk has no `runtime_tier` database column or CLI setting for selecting a VM (#3442)
  - **Upgrades are transactional.** `/update-nanoclaw` applies an update as a transaction with recovery on interruption, closing the gaps that could previously strand a half-upgraded install (#3195)
  - **Container gateway wiring is typed and admission-checked.** The gateway's per-session contribution (proxy env, trust anchors, credential-stub mounts) merges into the session spec before validation instead of riding raw Docker flags, and gateway selection becomes a registry (`NANOCLAW_GATEWAY_PROVIDER`, default `onecli`; installs that never set it behave as before). An unknown `NANOCLAW_RUNTIME_DRIVER` aborts startup, and drivers that cannot rebuild images in place deny `install_packages` and `--rebuild` at request time instead of failing later (#3308)
  - **Non-root hosts get an explicit container identity.** Every non-root host now passes `--user <uid>:<gid>` and `HOME=/home/node`. `CONTAINER_MEMORY_LIMIT` is validated at spawn: invalid values refuse the spawn with a named error instead of a raw Docker error; blank and `0` still mean uncapped (#3308)
  - **Telegram setup gets three improvements.** The pairing card correctly says the code is 6 digits. The approved group connection flow is documented in the skill. The wizard offers "add another Telegram bot" when one is already configured (#3431, #3352, #3480)
  - **`/add-codex` pins `@openai/codex` 0.146.0.** The previous pin defaults to a model OpenAI retires from Codex on 2026-08-31 and rejects newer models. Existing codex installs are not re-pinned by re-running the skill: edit the `@openai/codex` entry in `container/cli-tools.json` to `0.146.0`, rebuild the agent image, and restart (#3299)
  - **New installs use OneCLI gateway 1.41.0.** Existing 1.36.0 gateways remain compatible; see upstream `docs/onecli-upgrades.md` to upgrade. Registry sign-in verification now fails closed when a stored sign-in cannot be verified (#3277, #3339)
  - An unrecognized `engage_mode` logs a warning instead of silently dropping the message (#3317)
</Update>

<Update label="v2.2.0" description="2026-08-13" tags={["Breaking", "Feature", "Fix", "Skill"]}>
  - **Breaking: agent templates are Agent Plugins 1.0.0 directories** — `plugin.json` replaces `context/instructions.md` as the required manifest and discovery marker, MCP servers move from `.mcp.json` to a spec-shaped `mcp.json`, and persona, extra context files, and seeded tasks move under an `ai.nanoco.nanoclaw/` extension directory. Templates become portable to other plugin clients, and any conformant third-party plugin stamps as a NanoClaw agent. **Migration:** re-fetch templates from the registry — the pre-plugin layout now fails with a migration error; conversion steps for a local custom template are in [building a template](/templates/building#migrating-from-the-pre-plugin-layout) (#3220, #2909)
  - **Breaking: host modules use one lifecycle registry** — `onShutdown()` and `getShutdownCallbacks()` are gone from `response-registry.ts`. Custom host modules that imported either must move to the host lifecycle API in `src/host-lifecycle.ts`. **Migration:** follow `docs/host-lifecycle-migration.md` to detect affected code, update it, verify the cutover, or roll back (#3214)
  - **A stamped template updates in place instead of minting a duplicate agent** — `ncl groups create --template <ref>` against a group that already carries that plugin prints a dry-run plan of every plugin-owned surface that would change (plugin files, skills, MCP servers, persona, context files, tasks) and flags locally customized files whose edits would be lost. `--yes` applies it, `--id` picks among several stamped groups, `--new` deliberately stamps another agent. Memory, `plugin-data/`, user-added MCP servers, wiring, and sessions are never touched. Plugin-stamped MCP servers now carry an ownership marker and refuse direct edits through `ncl groups config add-mcp-server` / `remove-mcp-server` or the agent's `add_mcp_server` tool: update the plugin and restamp instead (#2909, #3220)
  - **Setup can stamp the first agent from a template** — the wizard offers the NanoClaw template library or the local `templates/` directory when creating the first agent, and `--template-path <ref>` or the advanced screen presets the pick. The choice survives wizard re-execs and reruns, a rerun over a partial install updates the stamped agent in place instead of duplicating it, and a stale local `templates/` warns and continues instead of aborting setup (#2909)
  - **Plugin MCP servers can declare a working directory** — `cwd` in `mcp.json` (fixed forms `./p`, `${PLUGIN_ROOT}[/p]`, `${PLUGIN_DATA}[/p]`) resolves to an absolute container path at runtime: providers that support it consume it natively, and Claude gets a `cd`-then-`exec` launch shim. A stdio server that omits `cwd` runs from the plugin root. `cwd` stays plugin-only — it is rejected at intake on raw payloads and stripped from stored servers that lack plugin provenance (#3220, #2909)
  - **Remote MCP servers can use Streamable HTTP** — register one with `ncl groups config add-mcp-server --name <name> --url <url>` (with optional `--headers`) or the existing admin-approved `add_mcp_server` tool; local stdio servers keep their `command` / `args` / `env` behavior. HTTPS is required except for `localhost` and `host.docker.internal`, and URLs carrying userinfo, a fragment, or a credential-looking query parameter are rejected, so remote credentials stay OneCLI-managed (#3092)
  - **`/add-tavily-tool` skill** — adds Tavily Search and Extract to selected agent groups as keyless remote MCP tools, bridged through a version-pinned `mcp-remote`. Aimed at providers without built-in `WebSearch`/`WebFetch`, and at Tavily's structured extraction (#3190)
  - **Agent-to-agent messaging no longer loses to Claude Code's built-in `SendMessage`** — that built-in addresses the SDK's own in-session subagents, so an agent that had just run `create_agent` reached for it by name and got `No agent named 'x' is currently addressable`, which reads as "the group was never provisioned" while the real path, `mcp__nanoclaw__send_message`, was never called. `SendMessage` joins `AskUserQuestion` in the disallowed-tool list, so the PreToolUse hook blocks it and points at the NanoClaw equivalent (#3187)
  - **Resolved approval cards keep their content** — an approved, rejected, or expired card keeps its title and request details and swaps the buttons for a muted line naming the decision and the actor, or the timeout reason. A startup sweep closes out cards left pending across a host restart, and the request text is persisted so a delayed resolution still renders in full (#3143)
  - **Scheduled tasks see their scheduled time, not their creation time** — a task message's `time` is now the effective scheduled occurrence, and a task-only `current_time` attribute carries the current wall clock with the weekday, in the agent group's timezone (#3154)
  - **Hosted iMessage setup provisions the line's user row and prints the number to text** — setup creates the user row through the project-secret API and prints the assigned phone number with one instruction: text that line once. That first message is the opt-in the delivery plane checks. Re-runs reuse the existing row, and a row that is already opted in short-circuits to success (#3181)
  - Setup dispatches failure help to the picked provider — a failed step during a non-Claude install no longer pushes you to install and sign in to the Claude CLI just to see what went wrong; Claude remains a guarded fallback only when it's already installed and signed in (#3170)
  - **Group-scoped agents can inspect and adjust their own wiring** — an agent may list, get, and request approved updates to the wiring for the chat it is in, limited to `engage_mode` and `engage_pattern`; wider updates, and any other agent group's wiring, are denied. Accumulated context messages no longer engage a warm container by themselves — a follow-up turn now needs an actual trigger message (#3137)
  - **`ensureUserDm` gains an opt-in privacy-safe logging mode** — security-sensitive flows can omit user IDs, handles, messaging-group IDs, and raw adapter errors from log data while keeping the non-identifying channel context (#3222)
  - **Release publication tolerates GitHub API propagation** — the release workflow retries bounded post-publication read-backs when the new release is not listed yet, or its immutable state is not visible yet. A real title, body, tag, or SHA mismatch still fails immediately (#3176)
  - `/update-nanoclaw` handles breaking changes that point at a documentation guide, not only at a migration skill — it reads each referenced guide and walks its detect, fix, verify, and rollback steps, and it reads its own newest version without touching the working tree. The hardened-image guide gained those sections (#3180)
  - The stale `add-gcal-tool`, `add-gmail-tool`, `get-qodo-rules`, and `qodo-pr-resolver` skills were removed (#3172)
  - The recommended hardened agent image is repinned to `hardened-2026-08-13` (#3236, #3182)
  - Docs: skills carry a single-responsibility integration rule, and the hardened-image guide states that `install_packages` covers apt and npm packages only (#3211, #3216)
</Update>

<Update label="v2.1.54" description="2026-08-01" tags={["Breaking", "Feature", "Fix"]}>
  - **Breaking: iMessage unified — one `imessage` channel, local or hosted backends** — `/add-imessage` now installs a single channel with two pluggable backends: local (this Mac's `chat.db`) or hosted (a native Photon line via photon.codes, no Mac relay), chosen at install or via `IMESSAGE_BACKEND=local|hosted`. The legacy Chat-SDK remote mode (`IMESSAGE_SERVER_URL`/`IMESSAGE_API_KEY`) is removed (#3164)
  - **Breaking: agent memory is provider-agnostic** — every provider now shares one OKF-compatible `memory/` tree instead of provider-native memory stores, with persona moved to `instructions.prepend.md`; memory reloads automatically on startup, `/clear`, and compaction. Groups still on legacy memory need `/migrate-memory` before their next spawn (#3012)
  - **Hardened agent images are an opt-in setup path** — setup can fetch a digest-pinned, multi-architecture image built and patched by Echo instead of building locally, with architecture, lockfile-label, and provenance checks before it's retagged onto the same local name a build would use. Building locally stays fully supported and needs no account (#3150)
  - **Agent containers get more hardening by default** — every spawn now runs with `--cap-drop=ALL`, `no-new-privileges`, and Docker's `--init`; a new `CONTAINER_PIDS_LIMIT` (default 2048) backstops fork bombs (#2748)
  - **Per-agent-group timezone override** — `ncl groups config update --timezone <IANA>` overrides the install timezone for that group's scheduling, run-log stamps, and container `TZ`; passing `""` clears it back to the install default (#3125)
  - **New groups can inherit an instance-wide default provider** — `DEFAULT_AGENT_PROVIDER` sets the provider a freshly created agent group starts on; it's stamped once at creation, and a group's own `ncl groups config update --provider` still overrides it (#2906)
  - **Agent templates can seed scheduled tasks** — a template's `tasks/*.md` files define a cron schedule, an optional script gate, and a prompt; template-seeded tasks are created paused so you can review them before activating (#3022)
  - **MCP server approval cards show the full payload** — `add_mcp_server` cards now render every field being applied (name, command, args, env), not just name and command, so an approver can no longer authorize args or env they never saw; secret-shaped values are redacted with a fingerprint (#2998)
  - The Vercel CLI is no longer baked into every agent image — install it with `/add-vercel` when a group actually needs to deploy (#3159)
  - Duplicate replies after mid-turn context compaction fixed — the SDK's `compact_boundary` event no longer surfaces as a synthetic result the poll loop mistakes for unwrapped output (#3083)
  - Claude rate-limit telemetry only aborts a turn on an actual rejection — informational `rate_limit_event` updates no longer abort healthy turns, and a rejection is classified as transient rate-limit or billing exhaustion instead of always reading as quota (#3077)
  - Telegram deep links use `telegram.me` instead of `t.me` (#3043)
</Update>
